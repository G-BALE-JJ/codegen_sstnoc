# ADR 0001：项目中枢与源码分离

## 状态

已接受

## 背景

SST codegen 项目需要在 `tilelang`、`TileOPs` 和 `RISC-V-CIM-Manycore-SST` 之外维护统一的规划、进度和技术决策。若把这些内容混在源码仓库中，容易造成改动边界不清晰，也不利于 agent 按职责执行任务。

项目早期只把 `codegen_sstnoc` 定位为规划中枢；当前已经演进为 out-of-tree CIM-TileIR / Golem exporter 原型工作区。

## 决策

采用 `codegen_sstnoc` 作为项目中枢和原型实现目录，用于存放计划、发现、进度、决策、辅助脚本、CIM-TileIR 原型代码、Golem backend exporter、示例和测试。

当前默认改动边界：

- `codegen_sstnoc/`：当前主工作区，可修改规划、文档、`tilelang_cim/`、examples、scripts 和 tests。
- `tilelang/`：默认只读，只有在正式接入 TileLang pass pipeline 时修改。
- `TileOPs/`：默认只读，当前只作为上层用例来源。
- `RISC-V-CIM-Manycore-SST/`：默认只读，当前通过 env/contract/artifact 解耦对接。

## 影响

- 项目结构更清晰。
- 当前原型可以快速迭代，同时不污染 TileLang 和硬件仓库。
- agent 更容易根据文档和测试执行任务。
- 需要持续维护当前路线文档，并将历史路线归档到 `docs/legacy/`。
